# معاينة حية — دورة حياة الطلب (Payment Fulfillment Gate)

هذه المعاينة تشغّل **التطبيق الحقيقي** (نفس مكوّنات React، نفس `RestaurantContext`،
نفس عميل الـAPI، ونفس سياسة البوابة `server/services/orderLifecycle.ts` وتحقّق صورة
الإشعار `server/services/storage/imageSniff.ts`) داخل DOM، مقابل خادم **في الذاكرة**
يحاكي مسارات Express/PostgreSQL بنفس المنطق (conditional claim + audit + SSE).

## التشغيل

```bash
npm run preview:gate
# أو مباشرة
npx vitest run --config e2e/live-preview/vitest.live.config.ts
```

يُنتج:

* سجل تشغيل كامل في الطرفية: كل طلب HTTP، وكل حدث SSE، وكل سطر تدقيق (audit)؛
* `e2e/live-preview/scenes.html` — لقطات الشاشات الثمانية كما رسمها التطبيق فعلاً،
  مع ورقة الأنماط المبنية (`npm run build`) مضمّنة داخلها، فتُفتح في أي متصفح.

## المشاهد

| # | المشهد | ما يُثبته |
|---|--------|-----------|
| ١ | الزبون يرسل الطلب | الطلب `AWAITING_PAYMENT` + خطوة الدفع الإلزامية على الشاشة |
| ٢ | المطبخ (KDS) | الطلب غير موجود كتكت، ومحاولة `PREPARING` تُرفض من الخادم (409) |
| ٣ | الكاشير | قسم «بانتظار دفع الزبون» — `WAITING_RECEIPT` بلا زر تأكيد |
| ٤ | الزبون يرسل الإشعار | رفع حقيقي عبر نافذة الدفع (XHR multipart) + تحقّق magic bytes |
| ٥ | الكاشير | القسم يتحول إلى `WAITING_VERIFICATION` مع الصورة والاسم والهاتف |
| ٦ | المطبخ | إشعار التحويل وحده لا يُدخل الطلب إلى المطبخ |
| ٧ | تأكيد الكاشير | المال + البوابة في عبارة واحدة، وبث `ORDER_RELEASED_TO_KITCHEN` → الزبون يرى «تم تأكيد الدفع، وجارٍ تجهيز طلبك.» بدون تحديث |
| ٨ | المطبخ | التكت يظهر فوراً «تحويل مؤكد — جاهز للبدء فوراً» ثم يبدأ التحضير |
| ٩ | تأكيدان متزامنان | إيصال واحد فقط: `201` + `200 alreadyConfirmed` |
| ١٠ | رفض الإشعار | `PAYMENT_REJECTED`، الطلب يبقى خارج المطبخ، والزبون يرى السبب وزر إرسال إشعار جديد |
| ١١ | إلغاء بعد التأكيد | `409` — لا يمكن للزبون حذف طلب مدفوع |
| ١٢ | الخلاصة | حالة كل طلب في «قاعدة البيانات» + سجل التدقيق + الأحداث المبثوثة |

## ما هو حقيقي وما هو محاكاة

* **حقيقي**: الواجهة بالكامل، سياق التطبيق، عميل الـAPI (بما فيه رفع XHR)، مساعد SSE،
  نصوص الواجهة العربية، سياسة البوابة على الخادم، والتحقق من صورة الإشعار.
* **محاكاة**: النقل HTTP، PostgreSQL، تخزين الكائنات، وأربع واجهات متصفح غير موجودة في
  jsdom (`EventSource`، `XMLHttpRequest`، `createObjectURL`، فك ترميز الصور). المنطق
  المحاكى مطابق لما تثبّته `src/tests/fulfillment-gate.test.ts` على ملفات المسارات الحقيقية.

## تشغيل الدورة الحقيقية (بيئة فيها PostgreSQL)

```bash
npm install                 # يحتاج الوصول إلى binaries.prisma.sh
export DATABASE_URL=... && npm run db:migrate && npm start   # API + الترحيلات :3001
npm run dev                 # الواجهة :5173 (بروكسي /api و/uploads إلى :3001)
```

* **الزبون**: افتح `http://localhost:5173/r/mureeh?qr=<qrToken>` (رمز طاولة حقيقي من شاشة
  الطاولات)، أضف أصنافاً، أرسل الطلب، ثم أرسل إشعار التحويل من نافذة الدفع.
* **الكاشير**: سجّل الدخول (بريد/كلمة مرور أو PIN) → تبويب **الكاشير (POS)** → لوحة
  «تحقق من إشعارات التحويلات»: أرسل `تأكيد` أو `رفض`.
* **المطبخ**: افتح **شاشة المطبخ (KDS)** على جهاز/تبويب آخر — سيظهر التكت لحظياً بعد
  التأكيد فقط، وبدون تحديث يدوي.

هذه المعاينة لا تعمل في الوعاء الحالي لأن `binaries.prisma.sh` محجوب (لا محرّك Prisma ⇒
لا `prisma generate`) ولا توجد قاعدة PostgreSQL.
